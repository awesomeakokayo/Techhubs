## 5. Knowledge checks and answer keys (internal)

### Stage 1 — Design Fundamentals (3 questions)

1. What is visual hierarchy?
   - · Using the largest font everywhere
   - **✔ Arranging elements so importance is clear at a glance**
   - · Adding more colours
   - · Centering all text
   - _Why:_ Hierarchy guides the eye by making relative importance obvious. · _level: understand_
2. Which pairing choice best improves readability?
   - · Low-contrast grey text on grey
   - **✔ A strong contrast between text and background that meets accessibility guidance**
   - · Decorative fonts for body text
   - · Random font sizes
   - _Why:_ Sufficient contrast and legible type make text readable. · _level: apply_
3. Why limit the number of type sizes and colours?
   - · To save storage
   - **✔ To create consistency and reduce visual noise**
   - · Because tools require it
   - · To slow the user
   - _Why:_ Constraints produce consistency and clarity. · _level: analyze_

### Stage 2 — UX Foundations (3 questions)

1. What is the purpose of a persona?
   - · To decorate a slide
   - **✔ To make user goals and constraints concrete enough to guide decisions**
   - · To replace testing
   - · To choose colours
   - _Why:_ Personas focus design decisions on real user needs. · _level: understand_
2. Why wireframe before visual design?
   - · Because colour is disallowed
   - **✔ To settle structure and flow cheaply before investing in visuals**
   - · To meet a deadline
   - · To avoid research
   - _Why:_ Low-fidelity structure is cheaper to change than polished visuals. · _level: understand_
3. Which research method best reveals why users struggle with a flow?
   - · A large survey
   - **✔ A moderated usability test where you observe them attempt the task**
   - · A focus group about colours
   - · Analytics page views alone
   - _Why:_ Observing real attempts reveals the causes behind problems; analytics show symptoms. · _level: analyze_

### Stage 3 — Figma Mastery (3 questions)

1. What is the benefit of a component variant?
   - · It deletes the original
   - **✔ It lets one component express multiple states cleanly**
   - · It adds animation
   - · It exports code
   - _Why:_ Variants group related states/props under one maintainable component. · _level: understand_
2. Why prefer auto layout over manually positioned frames?
   - · It is faster to draw once
   - **✔ Layout responds correctly when content or size changes**
   - · It looks nicer
   - · It exports PNGs
   - _Why:_ Auto layout keeps design resilient to content changes. · _level: understand_
3. What should developer handoff include?
   - · Only a screenshot
   - **✔ Component states, spacing, type styles and interaction notes**
   - · A private file with no comments
   - · Just colours
   - _Why:_ Handoff must communicate states, spacing, type and behaviour. · _level: apply_

### Stage 4 — Advanced UX (3 questions)

1. What is a good usability test task?
   - · “Do you like this?”
   - **✔ A realistic goal like “Find and buy a pair of running shoes”**
   - · A request to rate the colours
   - · A survey of preferences
   - _Why:_ Tasks should be realistic goals, not opinions or leading questions. · _level: apply_
2. Which is a genuine accessibility failure?
   - **✔ Contrast below the guideline for body text**
   - · Using system fonts
   - · A short page
   - · Blue buttons
   - _Why:_ Insufficient contrast makes content unreadable for many users and fails guidelines. · _level: understand_
3. Why design mobile-first?
   - · Mobile is more important
   - **✔ It forces prioritisation of content and constraints, which improves all screens**
   - · It is faster
   - · It needs no testing
   - _Why:_ Mobile-first forces focus and typically improves the desktop experience too. · _level: evaluate_

### Stage 5 — Portfolio & Case Studies (3 questions)

1. What makes a case study credible?
   - · Beautiful final screens only
   - **✔ The problem, the process, the decisions, and evidence of testing**
   - · A list of tools
   - · A long introduction
   - _Why:_ Credibility comes from reasoning and evidence, not just output. · _level: evaluate_
2. A stakeholder asks why you chose a layout. What should you reference?
   - · Personal taste
   - **✔ The user need and evidence from research or testing**
   - · A competitor only
   - · The deadline
   - _Why:_ Design decisions should be justified by user need and evidence. · _level: evaluate_
3. How should you describe an abandoned design direction?
   - · Hide it
   - **✔ Show it as a considered trade-off that led to a better solution**
   - · Blame the client
   - · Pretend it never existed
   - _Why:_ Iteration and trade-offs demonstrate judgement. · _level: understand_
