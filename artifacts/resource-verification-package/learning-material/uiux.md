## Stage 1 — Design Fundamentals

**Objective:** Apply core visual design principles — typography, colour, layout, hierarchy and Gestalt — to real screens.

**Success criteria:**
- Build a clear visual hierarchy
- Choose type and colour deliberately
- Use a grid and spacing system

### Instruction

Every great designer understands the principles behind visual communication. These are tools, not rules.

OBJECTIVE
Apply core visual design principles — typography, colour, layout, hierarchy and Gestalt — to real screens.

SUCCESS CRITERIA
• Build a clear visual hierarchy
• Choose type and colour deliberately
• Use a grid and spacing system

WORKED EXAMPLE
Design a login screen. Step 1: pick a 4-pt spacing scale and use only those values. Step 2: choose two text sizes and one accent colour. Step 3: align the form fields to a single axis with consistent gaps. Step 4: add visible focus states and check body-text contrast against 4.5:1.

COMMON MISTAKES
• Too many typefaces and sizes
• Low colour contrast
• Inconsistent spacing with no system

### Worked example

Design a login screen. Step 1: pick a 4-pt spacing scale and use only those values. Step 2: choose two text sizes and one accent colour. Step 3: align the form fields to a single axis with consistent gaps. Step 4: add visible focus states and check body-text contrast against 4.5:1.

## Stage 2 — UX Foundations

**Objective:** Ground design decisions in user needs through research, personas, information architecture and wireframes.

**Success criteria:**
- Choose appropriate research methods
- Turn findings into personas and journey maps
- Structure content with IA and wireframes

### Instruction

UX is about understanding people. Research what users need, map their experiences, and structure information clearly.

OBJECTIVE
Ground design decisions in user needs through research, personas, information architecture and wireframes.

SUCCESS CRITERIA
• Choose appropriate research methods
• Turn findings into personas and journey maps
• Structure content with IA and wireframes

WORKED EXAMPLE
Turn a complaint into a journey map. Step 1: write the user's goal. Step 2: list each step they took, in order. Step 3: mark the emotion and the exact point they dropped off. Step 4: write one problem statement — "New users cannot find X because Y" — that the design will address.

COMMON MISTAKES
• Designing without any user evidence
• Treating a persona as a fictional character rather than a decision tool
• Jumping to high-fidelity too early

### Worked example

Turn a complaint into a journey map. Step 1: write the user's goal. Step 2: list each step they took, in order. Step 3: mark the emotion and the exact point they dropped off. Step 4: write one problem statement — "New users cannot find X because Y" — that the design will address.

### Common mistakes
- Designing without any user evidence
- Treating a persona as a fictional character rather than a decision tool
- Jumping to high-fidelity too early

## Stage 3 — Figma Mastery

**Objective:** Use Figma fluently: components, variants, auto layout, prototyping and developer handoff.

**Success criteria:**
- Build reusable components with variants
- Use auto layout and constraints
- Prototype interactions and prepare handoff

### Instruction

Figma is the industry-standard design tool. Learn it deeply, components, auto-layout, and interactive prototypes.

OBJECTIVE
Use Figma fluently: components, variants, auto layout, prototyping and developer handoff.

SUCCESS CRITERIA
• Build reusable components with variants
• Use auto layout and constraints
• Prototype interactions and prepare handoff

WORKED EXAMPLE
Build a button component in Figma. Step 1: create variants for default, hover and disabled. Step 2: use auto-layout with padding and gap tokens. Step 3: place instances on a screen. Step 4: change the variant property once and confirm every instance updates — if it does not, your instances are detached.

COMMON MISTAKES
• Detaching components constantly
• Using absolute positioning instead of auto layout
• No naming convention, so handoff is confusing

### Worked example

Build a button component in Figma. Step 1: create variants for default, hover and disabled. Step 2: use auto-layout with padding and gap tokens. Step 3: place instances on a screen. Step 4: change the variant property once and confirm every instance updates — if it does not, your instances are detached.

### Common mistakes
- Detaching components constantly
- Using absolute positioning instead of auto layout
- No naming convention, so handoff is confusing

## Stage 4 — Advanced UX

**Objective:** Test designs with users and design inclusively and mobile-first.

**Success criteria:**
- Plan and run a usability test
- Identify and fix accessibility issues
- Design mobile-first

### Instruction

Move from making things look good to making things work well. Test with real users, fix what breaks, iterate.

OBJECTIVE
Test designs with users and design inclusively and mobile-first.

SUCCESS CRITERIA
• Plan and run a usability test
• Identify and fix accessibility issues
• Design mobile-first

WORKED EXAMPLE
Run a five-task usability test. Step 1: give each participant a goal, not instructions. Step 2: record completion, time and where they hesitate. Step 3: note verbatim quotes for each friction point. Step 4: prioritise the fixes by severity (blocker, major, minor) and state the evidence for each rating.

COMMON MISTAKES
• Leading participants to the answer
• Testing with too few or unrepresentative users
• Treating accessibility as a final checkbox

### Worked example

Run a five-task usability test. Step 1: give each participant a goal, not instructions. Step 2: record completion, time and where they hesitate. Step 3: note verbatim quotes for each friction point. Step 4: prioritise the fixes by severity (blocker, major, minor) and state the evidence for each rating.

### Common mistakes
- Leading participants to the answer
- Testing with too few or unrepresentative users
- Treating accessibility as a final checkbox

### Knowledge check (3 questions, server graded: yes)

1. What is a good usability test task?
   - “Do you like this?”
   - **✔ A realistic goal like “Find and buy a pair of running shoes”**
   - A request to rate the colours
   - A survey of preferences
   - _Answer:_ A realistic goal like “Find and buy a pair of running shoes” · _Why:_ Tasks should be realistic goals, not opinions or leading questions. · _Level:_ apply

2. Which is a genuine accessibility failure?
   - **✔ Contrast below the guideline for body text**
   - Using system fonts
   - A short page
   - Blue buttons
   - _Answer:_ Contrast below the guideline for body text · _Why:_ Insufficient contrast makes content unreadable for many users and fails guidelines. · _Level:_ understand

3. Why design mobile-first?
   - Mobile is more important
   - **✔ It forces prioritisation of content and constraints, which improves all screens**
   - It is faster
   - It needs no testing
   - _Answer:_ It forces prioritisation of content and constraints, which improves all screens · _Why:_ Mobile-first forces focus and typically improves the desktop experience too. · _Level:_ evaluate

## Stage 5 — Portfolio & Case Studies

**Objective:** Communicate design work through documented case studies and a presentable portfolio.

**Success criteria:**
- Document process and decisions
- Write a case study with evidence
- Present work clearly to an audience

### Instruction

A designer with no portfolio is invisible. Document your thinking, not just final designs.

OBJECTIVE
Communicate design work through documented case studies and a presentable portfolio.

SUCCESS CRITERIA
• Document process and decisions
• Write a case study with evidence
• Present work clearly to an audience

WORKED EXAMPLE
Turn a project into a case study. Step 1: state the problem and the constraints. Step 2: show two alternative directions you rejected and why. Step 3: present the final design. Step 4: give the outcome — a metric, a quote, or a clearly labelled expected effect. Show the reasoning, not just the mockups.

COMMON MISTAKES
• Showing only polished visuals with no reasoning
• Claiming results without evidence
• Hiding failed iterations that show learning

### Worked example

Turn a project into a case study. Step 1: state the problem and the constraints. Step 2: show two alternative directions you rejected and why. Step 3: present the final design. Step 4: give the outcome — a metric, a quote, or a clearly labelled expected effect. Show the reasoning, not just the mockups.

### Common mistakes
- Showing only polished visuals with no reasoning
- Claiming results without evidence
- Hiding failed iterations that show learning
