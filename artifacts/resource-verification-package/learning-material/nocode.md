   - To reduce content
   - _Answer:_ So layout adapts to different screen sizes without breaking · _Why:_ Breakpoints let the layout adapt across devices. · _Level:_ apply

   - _Answer:_ A CMS collection the client can add to · _Why:_ A CMS collection lets non-technical users add content safely. · _Level:_ analyze

## Stage 2 — App Building

**Objective:** Build a functional app with data, auth and logic.

**Success criteria:**
- Model data
- Add authentication
- Build workflows

### Instruction

Build functional applications with user accounts, databases, and business logic, all without code.

OBJECTIVE
Build a functional app with data, auth and logic.

SUCCESS CRITERIA
• Model data
• Add authentication
• Build workflows

WORKED EXAMPLE
Build a two-table app. Step 1: create a tasks collection with a status field. Step 2: add a form that creates a task. Step 3: build a list view filtered to open tasks. Step 4: mark one task complete and confirm it leaves the open view.

COMMON MISTAKES
• Leaving data publicly readable
• Putting all logic in the UI with no data rules

### Worked example

Build a two-table app. Step 1: create a tasks collection with a status field. Step 2: add a form that creates a task. Step 3: build a list view filtered to open tasks. Step 4: mark one task complete and confirm it leaves the open view.

### Common mistakes
- Leaving data publicly readable
- Putting all logic in the UI with no data rules

### Knowledge check (3 questions, server graded: yes)

1. In a no-code app, what is a workflow?
   - A design file
   - **✔ An automated sequence of steps triggered by user actions or events**
   - A database table
   - A colour theme
   - _Answer:_ An automated sequence of steps triggered by user actions or events · _Why:_ Workflows automate logic in response to triggers. · _Level:_ understand

2. Why are database privacy rules important?
   - They speed the app
   - **✔ They stop users reading or changing data that is not theirs**
   - They improve the UI
   - They are optional
   - _Answer:_ They stop users reading or changing data that is not theirs · _Why:_ Privacy rules enforce who can read/write which records. · _Level:_ evaluate

3. You need to show each user only their own items. What must you do?
   - Show all items
   - **✔ Filter the data query by the logged-in user**
   - Hide items with CSS
   - Ask users to ignore others
   - _Answer:_ Filter the data query by the logged-in user · _Why:_ Data must be filtered by ownership in the query and enforced by rules. · _Level:_ apply

## Stage 3 — Automation

**Objective:** Connect apps and services with automation.

**Success criteria:**
- Build trigger/action automations
- Connect APIs without code
- Handle errors

### Instruction

Connect tools, trigger actions, and automate repetitive tasks across any platform.

OBJECTIVE
Connect apps and services with automation.

SUCCESS CRITERIA
• Build trigger/action automations
• Connect APIs without code
• Handle errors

WORKED EXAMPLE
Connect a form to a database and a notification. Step 1: on submission, create a record. Step 2: send a confirmation email to the respondent. Step 3: post a message to a team channel. Step 4: add one conditional that routes submissions with missing fields to a review queue instead.

COMMON MISTAKES
• No error handling
• Automating a process that changes constantly

### Worked example

Connect a form to a database and a notification. Step 1: on submission, create a record. Step 2: send a confirmation email to the respondent. Step 3: post a message to a team channel. Step 4: add one conditional that routes submissions with missing fields to a review queue instead.

### Common mistakes
- No error handling
- Automating a process that changes constantly

### Ungraded practice
**Practice: Automation**

DO THIS NOW
Build an automation with a trigger and at least two actions, add a filter, and describe what happens when one step fails.

This is ungraded practice. Complete it before the knowledge check so you can answer from experience, not memory.

### Knowledge check (3 questions, server graded: yes)

1. In Zapier/Make, a trigger is…
   - The final result
   - **✔ The event that starts an automation**
   - A data field
   - A colour scheme
   - _Answer:_ The event that starts an automation · _Why:_ A trigger is the event that starts the automation. · _Level:_ recall

2. How can you connect to an API without code?
   - Write a server
   - **✔ Use a no-code HTTP/webhook action in the automation tool**
   - Email the API provider
   - Use CSS
   - _Answer:_ Use a no-code HTTP/webhook action in the automation tool · _Why:_ No-code tools provide HTTP request steps to call APIs directly. · _Level:_ apply

3. Why add error handling to an automation?
   - To make it slower
   - **✔ So a single failed step does not silently corrupt the process**
   - To increase cost
   - To avoid testing
   - _Answer:_ So a single failed step does not silently corrupt the process · _Why:_ Without error handling, failures strand data or cause duplicate work. · _Level:_ evaluate
